Problem Statement

The ML Serving Challenge

  • Individual Processing: High latency, low throughput
  • Static Batching: Poor adaptation to workload changes
  • Manual Tuning: Requires constant optimization
  • Memory Safety: Python GIL and memory management issues

Traditional Batching Problems


# Static batching approach
batch_size = 8  # Fixed, doesn't adapt
wait_time = 100ms  # Fixed, not optimal

# Problems:
# 1. High load → underutilized batches
# 2. Low load → excessive latency
# 3. Variable request sizes → memory issues
# 4. No learning from past performance
Result: Suboptimal performance across different workload patterns

CORK = Coordinated Request Batching
Adaptive algorithm that learns optimal batching parameters

CORK Algorithm Deep Dive

Core Concepts

  • Adaptive Parameters: o_a, o_b, wait_time
  • Training Phases: Periodic learning cycles
  • Least Squares Optimization: Mathematical parameter tuning
  • Performance Model: processing_time = o_a × batch_size + o_b

Algorithm Flow


1. Initialize with default parameters
   ├─ o_a = 0.001 (time per item)
   ├─ o_b = 0.01  (base overhead)
   └─ wait_time = 50ms

2. Training Phase (collect N samples)
   ├─ Form batches based on current parameters
   ├─ Measure: batch_size, processing_time
   └─ Store observations: (x_i, y_i)

3. Optimization Phase
   ├─ Solve: processing_time = o_a × batch_size + o_b
   ├─ Use least squares regression
   └─ Update parameters with constraints

4. Apply & Repeat
   ├─ Use new parameters for batching
   └─ Start next training cycle

Mathematical Foundation

The algorithm solves this linear system:


[ n      Σx_i    ] [ o_b ]   [ Σy_i      ]
[ Σx_i   Σx_i²   ] [ o_a ] = [ Σ(x_i×y_i) ]

Where:
- n = number of observations
- x_i = batch size for observation i  
- y_i = processing time for observation i
- o_a, o_b = parameters to optimize
Goal: Minimize prediction error while respecting latency constraints

Async Architecture


// Controller loop using tokio::select!
async fn controller_loop() {
    loop {
        tokio::select! {
            // New request arrives
            Some(req) = request_receiver.recv() => {
                requests.push(req);
                if should_process_batch(&requests) {
                    process_batch(requests.drain(..).collect()).await;
                }
            }
            
            // Batch timer expires
            _ = batch_timer.tick() => {
                if !requests.is_empty() {
                    process_batch(requests.drain(..).collect()).await;
                }
            }
            
            // Shutdown signal
            _ = shutdown_receiver.recv() => break,
        }
    }
}

Type Safety & Error Handling


#[derive(thiserror::Error, Debug)]
pub enum BatchError {
    #[error("Request timed out after {timeout_ms}ms")]
    Timeout { timeout_ms: u64 },
    
    #[error("Service unavailable: {reason}")]
    ServiceUnavailable { reason: String },
    
    #[error("Processing failed: {source}")]
    ProcessingError { 
        source: Box<dyn std::error::Error + Send + Sync> 
    },
}

// Safe channel communication
type RequestChannel<T> = mpsc::UnboundedSender<RequestMessage<T>>;
type ResponseChannel<R> = oneshot::Sender<Result<R, BatchError>>;
